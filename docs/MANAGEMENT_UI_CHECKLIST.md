# Management UI functional checklist

This checklist covers the management pages in the current frontend. It records existing backend behavior and concrete checks for Profiles/accounts, Settings, and the publication center. Do not use real credentials, connect an external account, retry a real publication, or confirm/publish a post while running these checks. Use an isolated local database and disposable fixture records only.

## Evidence rules

- `Unit/integration` means a Vitest run with mocked API responses. It does not prove browser layout or a real server round trip.
- `Browser` means an operator completed the listed interaction in the running app and checked the resulting UI and Network/API readback. A screenshot alone proves only the visible state in that image.
- Use `Not run` until the listed action was completed. If only part of a row was checked, record `Partial` and name the untested portion.
- Screenshots and logs must not show credentials, secret values, environment values, or unredacted pairing codes.

| Area | Existing contract | Limits relevant to this checklist |

| Translation config | `GET /api/translation-configs`; `POST /api/translation-configs` with provider and nonsecret configuration fields. | No update/delete endpoint or visible existing-config editor was found in the current contract. Do not test or imply editing existing configs. The API deliberately clears `credential_ref` on create. |
| Publication center | `GET /api/publications?profile_id=…`; retry `POST /api/publications/retry` with `{publication_id}`; uncertain outcome `POST /api/publications/{id}/confirm` with `{remote_url, remote_id?}` or `POST /api/publications/{id}/cancel`; remove local record `DELETE /api/publications/{id}`. | Retry may invoke a real remote publish. Browser checks must use mocks or a local fixture that cannot reach a remote service. Removal is local-only; confirmation is for a real already-published URL and must not be fabricated in production data. The current list renders record details inline; no separate detail route/panel or pagination contract was found. |

## Current test coverage and gaps

Existing Vitest coverage includes account-management composable/API tests and app-level interactions for account create/edit, profile account attachment, connection diagnostics, publication grouping/retry/confirmation/removal, and profile-scoped publication history. `PublicationCenterView.vue` has a wrapper test that stubs `PublicationList`; it does not by itself exercise list rendering or actions. Before this audit, Settings coverage checked that `google-gtx` hides the credential input, but did not verify saving through the UI; profile create/readback was also missing. This audit adds those flows, strengthens the deactivation test to assert one request and disabled-list movement, and tests PublicationList's tabs, empty confirmation URL, and scoped refresh. They still do not establish backend persistence or browser layout.
